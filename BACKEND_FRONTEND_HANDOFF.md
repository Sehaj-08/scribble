## 1. Backend Overview

### Tech Stack

| Layer | Technology | Version |
|---|---|---|
| Runtime | Node.js (ESM modules) | — |
| HTTP Framework | Express | `^5.2.1` |
| WebSocket Library | `ws` (npm package) | `^8.21.3` |
| Config | `dotenv` | `^17.4.2` |
| Dev server | `nodemon` via `npx` | — |

> **Note**: The `package.json` also lists `"websockets": "^0.2.0"` but it is **never imported** anywhere in the source. Treat it as unused.

### Entry Point

```
backend/
  src/
    app.js            ← Single true entry point (nodemon points here)
    server.js         ← Empty file (unused)
    config/
      constants.js    ← ROOM_STATES, STROKE_EVENTS, GUESS_EVENTS, CHOOSE_WORD enums
    controllers/
      room.controllers.js  ← HTTP handler functions
    routes/
      room.routes.js       ← Express route definitions
    services/
      gameServices.js      ← All game logic (timer, strokes, guessing, round management)
    sockets/
      socketManager.js     ← WebSocket server bootstrap & message dispatch
    store/
      roomStore.js         ← In-memory rooms object (global singleton)
```

### How the Server Starts (`src/app.js`)

1. Loads `.env` via `dotenv/config`.
2. Creates an Express app, registers `express.json()` middleware.
3. Mounts the room router at `/api/rooms`.
4. Creates an `http.Server` wrapping the Express app.
5. Calls `initWebSockets(server)` to attach a `ws` WebSocket server to the **same HTTP server** (shared port).
6. Listens on `process.env.PORT` or falls back to **`8000`**.

> ✅ HTTP and WebSocket traffic both run on the **same port** (default `8000`).

## 2. Data Models

All state is held in a single in-memory JavaScript object `rooms` (keyed by room ID).  
**There is no database.** All data is lost on server restart.

### Room Object

```js
rooms[roomId] = {
  // ── set at creation ──────────────────────────────
  players:            [],          // Array<Player> — all players ever joined
  state:              "WAITING",   // current game state (see §3)
  strokes:            [],          // Array<StrokeMessage> — stroke history for current round
  totalRounds:        5,           // fixed at room creation, never changes
  currentRounds:      0,           // increments at the start of each round
  alreadyMadeDrawers: [],          // Array<Player> — used for drawer rotation

  // ── set during play ──────────────────────────────
  drawer:             <Player>,    // reference to the current drawer player object
  word:               "capybara",  // current round word (trimmed + lowercased)
  candidateArray:     [],          // Array<{wordId, word}> — 3 word choices sent to drawer
  time:               60,          // seconds remaining (counts down)
  timer:              <Interval>,  // setInterval handle for the round timer
}
```

**Source**: `room.controllers.js:17–24`, `gameServices.js` (various)

### Player Object

```js
{
  playerId:     "abc123xyz",  // random alphanumeric string (8 chars)
  socket:       <ws.WebSocket | null>,  // null if not connected / disconnected
  hasGuessed:   false,        // true once this player guesses correctly this round
  lastStrokeId: 0,            // highest strokeId received (used for sync)
  score:        0,            // cumulative score across rounds
}
```

**Source**: `room.controllers.js:30–36`, `room.controllers.js:55–61`

> ⚠ **The `playerId` returned from `join_room` is not sent back in the HTTP response** (see §4 — the join response only says `"Player Entered the fucking room"`). The frontend has **no way to know its own `playerId`** after joining. This is a confirmed gap.

### Word Candidate Object

```js
{
  wordId: 3,          // integer index into the animals array
  word:   "Lemur"     // raw string (case-preserved in transit; lowercased when stored as room.word)
}
```

## 3. Game States & Transitions

### State Enum (`src/config/constants.js`)

| Constant | String Value | Meaning |
|---|---|---|
| `ROOM_STATES.waiting` | `"WAITING"` | Room created, fewer than 2 connected players |
| `ROOM_STATES.choosing_words` | `"CHOOSING_WORD"` | Drawer is picking a word |
| `ROOM_STATES.drawing` | `"DRAWING"` | Active drawing/guessing phase |
| `ROOM_STATES.round_ended` | `"ROUND_ENDED"` | Round just ended (transient) |
| `ROOM_STATES.starting_new_round` | `"STARTING_NEW_ROUND"` | Between rounds, about to call `startRound` again |

### State Transition Diagram

```
         ┌──────────────────────────────────────────────────────┐
         │  A player with a WS connection joins and ≥2 players  │
         ▼                                                       │
      WAITING ──────────────────────────────────────────────────┘
         │
         │ startRound() called (room.currentRounds increments)
         ▼
   CHOOSING_WORD ◄─────────────────────────────────────────────────────┐
         │                                                               │
         │ checkWord(): drawer sends choose_word, word is valid          │
         ▼                                                               │
      DRAWING ─────────────────────────────────────────────────────┐   │
         │                                                           │   │
    (two exits)                                                      │   │
         │                                                           │   │
    [A] timer reaches 0                                             │   │
    [B] all non-drawer guessed correctly                            │   │
         │                                                           │   │
         ▼                                                           │   │
    ROUND_ENDED (transient)                                          │   │
         │                                                           │   │
    [if currentRounds < totalRounds AND ≥2 players connected]       │   │
         │                                                           │   │
         ├──► STARTING_NEW_ROUND ──► startRound() ──────────────────┘   │
         │                                                               │
    [if currentRounds < totalRounds AND only 1 player left]             │
         │                                                               │
         └──► WAITING ──────────────────────────────────────────────────┘
         │
    [if currentRounds >= totalRounds]
         │
         ▼
      GAME_OVER (no dedicated state — server broadcasts scores then stops)
```

**Source**: `gameServices.js:8–20`, `gameServices.js:29`, `gameServices.js:179–223`, `gameServices.js:547–586`, `gameServices.js:277–313`

### Round Lifecycle Detail

1. **`startRound()` is called** when a new WS connection arrives and `room.state === WAITING`.
2. `room.currentRounds` increments; all `player.hasGuessed` reset to `false`, all `player.lastStrokeId` reset to `0`.
3. A drawer is selected (random on round 1; rotation-with-history on subsequent rounds).
4. Three word candidates are picked from a hard-coded 10-animal list and stored in `room.candidateArray`.
5. `word_choice` message sent **only to the drawer's socket**.
6. State → `CHOOSING_WORD`.
7. Drawer sends `choose_word` event → `checkWord()` validates → `room.word` set → timer starts → state → `DRAWING`.
8. Non-drawer players get a `{ message: "Game has fucking started" }` broadcast (see §5 for the exact payload).
9. Timer ticks every 1 s, broadcasting `time-ticking` to all players.
10. Round ends either by timer or all-guessed-correctly path.

## 4. HTTP API

**Base URL**: `http://localhost:8000/api/rooms`

> There is **no authentication** — no tokens, cookies, or headers are checked by any endpoint.

---

### `GET /api/rooms/rooms` — Create Room

**Note**: The route is `router.get("/rooms", create_room)` mounted at `/api/rooms`, making the full path `/api/rooms/rooms`. This is likely a naming mistake but is confirmed in the code.

**Source**: `room.routes.js:5`, `room.controllers.js:8–42`

**Request**: No body or query params required.

**Response** (`201 Created`):
```json
{
  "roomId": "AB3XK",
  "playerId": "k7f2mn9q"
}
```

| Field | Type | Description |
|---|---|---|
| `roomId` | string | 5-char uppercase alphanumeric room ID |
| `playerId` | string | 8-char alphanumeric ID for the creating player |

**Room created with**:
- `state: "WAITING"`, `totalRounds: 5`, `currentRounds: 0`
- Creator's player object pre-added to `players[]` with `score: 0`, `socket: null`

**Error**: None documented (room ID collision is handled by retry loop internally).

---

### `POST /api/rooms/join_rooms/:room_id` — Join Room

**Source**: `room.routes.js:6`, `room.controllers.js:44–65`

**Request**:
- URL param: `room_id` (the 5-char room ID)
- No body required.

**Response** (`201 Created`):
```
"Player Entered the fucking room"
```
> ⚠ **Critical Gap**: The response is a raw string, **not JSON**, and does **not** return the joining player's `playerId`. The frontend cannot know its own ID after calling this endpoint. This must be fixed or worked around.

**Error** (`400 Bad Request`):
```
"Room no longer exists"
```
(Raw string, not JSON.)

## 5. WebSocket Contract

### Connection

**URL pattern**:
```
ws://localhost:8000?roomId=<ROOM_ID>&playerId=<PLAYER_ID>
```

**Query Parameters**:
| Param | Required | Description |
|---|---|---|
| `roomId` | ✅ | Room ID obtained from the create or join HTTP call |
| `playerId` | ✅ | Player ID obtained from the create HTTP call |

**Connection Flow**:
1. Server validates `roomId` exists → closes with code `1008 "Room not found"` if not.
2. Server finds `player` in `room.players` by `playerId` → closes with `1008 "Player doesnt belongs to this room"` if not found.
3. On success: `player.socket` is set; `player.score` is **reset to 0** (⚠ see §7).
4. `player_joined` is broadcast to all **other** connected players.
5. `syncStrokes()` is called for the newly connected player.
6. `startRound()` is called if `room.state === WAITING`.

**Source**: `socketManager.js:8–73`

---

### Close / Disconnect Behavior

When a socket closes, `disconnection(playerId, room, roomId, socket)` runs:

- Player is **not removed** from `room.players`; their `socket` is set to `null`.
- If the disconnected player was the **drawer**:
  - `room.state` → `ROUND_ENDED`; timer cleared.
  - Broadcasts a raw string to all remaining players: `"Drawer humara kayar tha leave krr gya bitch!!!"` (see §7 — this needs to be replaced with a proper event).
  - If `currentRounds < totalRounds` and ≥ 2 players remain → `STARTING_NEW_ROUND` → `startRound()`.
  - If only 1 player remains → `WAITING`.
  - If `currentRounds >= totalRounds` → broadcasts `Players score` to remaining players.
- If all players disconnect → room is deleted from `rooms`.
- If exactly 1 player remains → timer cleared, state → `WAITING`, sends `{ message: "Waiting for players to fucking join" }`.

**Source**: `gameServices.js:253–346`

---

### Messages: Client → Server

All messages must be sent as **JSON strings** (`JSON.stringify()`).

Every message **must** have a `type` field.

---

#### `stroke_point` — Draw a stroke point

Sent by the **drawer only** during `DRAWING` state.

```json
{
  "type": "stroke_point",
  "strokeId": 7,
  "x": 142.5,
  "y": 88.0
}
```

> ⚠ The exact fields beyond `type` and `strokeId` are **not validated or documented** by the backend. The backend stores the entire `message` object verbatim in `room.strokes[]` and re-broadcasts it to guessers. The frontend must define and consistently use its own schema. The only field the backend reads is `strokeId` (for sync tracking).

**Backend behaviour** (`handleStrokes`):
- Validates `room.state === DRAWING`.
- Validates `playerId === room.drawer.playerId` — non-drawers are silently ignored.
- Pushes `message` into `room.strokes[]`.
- Sends the raw `message` to all connected non-drawer players.
- Updates `player.lastStrokeId = message.strokeId` on each guesser.

**Source**: `gameServices.js:428–468`, `constants.js:12`

---

#### `stroke_end` — End of a stroke

Defined in `STROKE_EVENTS.END = "stroke_end"` (`constants.js:13`) but **never handled** in `socketManager.js` or `gameServices.js`.

> ⚠ **Dead constant** — the backend ignores `stroke_end` messages entirely. The frontend should not rely on the server to handle stroke boundaries.

---

#### `guess` — Submit a word guess

Sent by **non-drawer players** during `DRAWING` state.

```json
{
  "type": "guess",
  "text": "capybara"
}
```

**Backend behaviour** (`checkGuess`):
- Silently returns if `room.state === ROUND_ENDED`.
- Logs a warning (but does **not return**) if `room.state !== DRAWING`.
- Silently ignores if `message.text` is falsy or if the sender is the drawer.
- Compares `message.text.trim().toLowerCase()` against `room.word` (already lowercase).
- **Correct guess**: broadcasts `correct_guess` event; awards `room.time` points to the guesser; if all non-drawer connected players have guessed → ends round.
- **Wrong guess**: broadcasts `chat` event to all players who haven't guessed yet.

**Source**: `gameServices.js:470–603`, `constants.js:17–19`

---

#### `choose_word` — Drawer selects a word

Sent by the **drawer only** during `CHOOSING_WORD` state.

```json
{
  "type": "choose_word",
  "wordId": 3
}
```

| Field | Type | Description |
|---|---|---|
| `wordId` | number | Must match one of the `wordId` values from the `word_choice` event |

**Backend behaviour** (`checkWord`):
- Validates `room.state === CHOOSING_WORD`.
- Validates `playerId === drawer.playerId`.
- Looks up `wordId` in `room.candidateArray`.
- Sets `room.word = theWord.word.trim().toLowerCase()`.
- Changes state to `DRAWING`.
- Starts the 60-second timer.
- Broadcasts `{ message: "Game has fucking started" }` to all non-drawer players.

**Source**: `gameServices.js:606–646`, `constants.js:21–23`

**Sent to**: All currently-connected players **except** the new one.

**Sent to**: Drawer only.

```json
{
  "type": "word_choice",

    { "wordId": 7, "word": "Platypus" },
    { "wordId": 5, "word": "Narwhal" }

```

**Source**: `gameServices.js:140–148`

#### `time-ticking` — Timer countdown

**Sent to**: All players every second during `DRAWING` state.

```json
{
  "type": "time-ticking",
  "time": 42
}
```

Starts at `60` and counts down to `0`. The server clears the interval and ends the round when `time <= 0`.

**Source**: `gameServices.js:167–228`

---

#### Round-ended (timer expiry) — Unnamed event ⚠

When the timer reaches 0, the server broadcasts to all players:

```json
{
  "message": "Aye kya rheee lawdee!!",
  "word": "capybara"
}
```

> ⚠ **No `type` field.** The frontend must detect this by the presence of the `word` field. The `word` field reveals the correct answer. This payload needs a `type` field (e.g. `"round_ended"`) to be properly handled.

**Source**: `gameServices.js:190–196`

---

#### Round-started (word chosen) — Unnamed event ⚠

Sent to all non-drawer players when the drawer picks a word:

```json
{
  "message": "Game has fucking started"
}
```

> ⚠ **No `type` field and no useful data.** The frontend cannot learn: who is the drawer, what the word length is, or what the masked word looks like. This is a significant gap.

**Source**: `gameServices.js:639–641`

---

#### `correct_guess` — A player guessed correctly

**Sent to**: All players (including the guesser and drawer).

```json
{
  "type": "correct_guess",
  "player": "k7f2mn9q"
}
```

> ⚠ Score awarded is NOT included. The frontend must track scores locally, or wait for the final `Players score` event.

**Source**: `gameServices.js:507–512`

---

#### `chat` — Wrong guess becomes a chat message

**Sent to**: All connected players who have **not** yet guessed correctly.

```json
{
  "type": "chat",
  "text": "narwhal",
  "playerId": "k7f2mn9q"
}
```

> ⚠ **Bug**: The `playerId` field is set to `player.playerId` from the broadcasting loop iteration, **not** from the guesser's ID. This means every recipient of the wrong guess chat message sees their **own** `playerId` in the message, not the sender's.

**Source**: `gameServices.js:592–600`

---

#### `Players score` — Final scores (game over)

**Sent to**: Each player **individually** with only **their own** score.

```json
{
  "type": "Players score",
  "score": 234
}
```

> ⚠ **Critical Gap**: Each player only receives their own score. There is no broadcast of all players' scores together. The frontend cannot display a leaderboard with all players' final scores.

**Source**: `gameServices.js:13–18`, `gameServices.js:215–222`, `gameServices.js:307–311`, `gameServices.js:580–585`

---

#### Drawer-left notification — Unnamed event ⚠

When the drawer disconnects mid-round, all remaining players receive:

```json
"Drawer humara kayar tha leave krr gya bitch!!!"
```

> ⚠ **Raw string, not a JSON object.** `JSON.parse()` on this will return a plain string, not an object. The frontend must handle this as a string or the server must fix this to send a proper typed event.

**Source**: `gameServices.js:283`

#### Waiting notification — Unnamed event ⚠

When only 1 player remains:

```json

}
```

> ⚠ No `type` field.

**Source**: `gameServices.js:338–341`

### Stroke Synchronization (Late-Join / Reconnect)

`syncStrokes(room, player)` is called immediately on every new WebSocket connection.

**Logic** (`gameServices.js:398–426`):
- If `room.state !== DRAWING` → no-op (does nothing).
- If `room.strokes.length === 0` → no-op.
- Filters `room.strokes` for all strokes where `stroke.strokeId > player.lastStrokeId`.
- Sends each missing stroke directly to the joining player's socket.
- Updates `player.lastStrokeId` to the last sent stroke's ID.

> ✅ Late joiners during `DRAWING` will receive all strokes they missed.  
> ⚠ On reconnect, `player.lastStrokeId` is **not reset** (only reset at `startRound()`), so sync should work correctly for mid-round reconnects.  
> ⚠ **`strokeId` must be monotonically increasing integers** set by the frontend/drawer. The backend does not generate `strokeId` — it trusts whatever the drawer sends.

## 6. Frontend Integration Guide

### Screen ↔ State Mapping

| Frontend Screen | Backend Condition |
|---|---|
| Home / Create / Join | No WS connection needed |
| Lobby / Waiting Room | WS connected, `room.state === "WAITING"` |
| Word Selection (drawer only) | Received `word_choice` event |
| Drawing (drawer) | Received round-start broadcast (`{ message: "Game has fucking started" }`) |
| Guessing (guesser) | Same trigger as above |
| Round Summary | Received unnamed round-end event with `word` field |
| Game Over / Leaderboard | Received `Players score` event |

---

### Actions the Frontend Can Perform & Conditions

| Action | When Allowed | How |
|---|---|---|
| Create room | Anytime | `GET /api/rooms/rooms` |
| Join room | Room exists, not yet WS-connected | `POST /api/rooms/join_rooms/:room_id` |
| Connect WS | After create/join, have `roomId` + `playerId` | WS connect with query params |
| Send stroke | `room.state === DRAWING` && current player is drawer | Send `stroke_point` message |
| Submit guess | `room.state === DRAWING` && current player is NOT drawer | Send `guess` message |
| Choose word | Received `word_choice` event (drawer only) | Send `choose_word` message |

---

### Frontend State to Maintain

The backend does not send periodic state snapshots. The frontend must maintain:

| Data | Source |
|---|---|
| Own `playerId` | HTTP create response (⚠ not available after join — gap) |
| Own `roomId` | HTTP create/join response |
| Other players list | Build from `player_joined` events; no full player list is ever sent |
| Who is the current drawer | ⚠ Not sent by backend — **critical gap** |
| Current word (guesser masked) | ⚠ Not sent — **critical gap** |
| Word length hint | ⚠ Not sent — **critical gap** |
| Timer countdown | Receive `time-ticking`, display `time` |
| Stroke canvas | Receive `stroke_point` messages, render on canvas |
| Chat messages | Receive `chat` events |
| Who has guessed | Receive `correct_guess` events, track locally |
| Current round number | ⚠ Not sent — **critical gap** |
| Own score | Accumulate locally from `correct_guess` + `room.time` at guess time; confirmed at `Players score` |
| Other players' scores | ⚠ Not sent until game over, and even then only individually — **critical gap** |

---

### What the Backend Does NOT Send (Confirmed Gaps)

| Missing Information | Impact |
|---|---|
| `playerId` in join HTTP response | Joiner cannot authenticate with WS |
| Full player list on connection | Frontend cannot show lobby with all players |
| Drawer identity on round start | Frontend doesn't know who is drawing |
| Word length / masked word for guessers | No visual hint like `_ _ _ _ _` |
| Current round number | Can't show "Round 3 of 5" |
| All players' scores in real-time | Can't show live leaderboard |
| All players' final scores at game end | Can't show full leaderboard at end |
| `type` field on several server events | Fragile event detection required |
| Any acknowledgement of WS messages | No way to confirm server received strokes/guesses |
| Reconnection grace period timer | Noted as TODO in `Things_To_DoYet.md` |

## 7. Risks & Unknowns

### Confirmed Bugs

| # | Location | Description |
|---|---|---|
| B1 | `gameServices.js:592–600` | `chat` message sends recipient's own `playerId`, not the sender's |
| B2 | `gameServices.js:283` | Drawer-left notification is a raw string, not a JSON object |
| B3 | `socketManager.js:33` | `player.score = 0` on every WS connection — reconnecting mid-game resets score to 0 |
| B4 | `gameServices.js:189–196` | Round-end event has no `type` field |
| B5 | `gameServices.js:639–641` | Round-start event for guessers has no `type` field and no useful data |
| B6 | `gameServices.js:338–341` | Waiting notification has no `type` field |
| B7 | `room.controllers.js:63` | Join room returns raw string not JSON; `playerId` not returned |

### Confirmed Gaps (Backend Features Missing)

| # | Description | Workaround Possible? |
|---|---|---|
| G1 | No drawer identity broadcast | Backend must send drawer `playerId` to all at round start |
| G2 | No word length / masked word for guessers | Backend must send word length |
| G3 | No current round number broadcast | Backend must send `currentRounds` / `totalRounds` |
| G4 | No full player list broadcast (lobby) | Backend must send initial player list on connection |
| G5 | Scores sent individually, not collectively | Backend must send all scores together at game end |
| G6 | `stroke_end` event defined but never handled | Frontend should encode stroke boundaries differently (e.g., a flag in `stroke_point`) |
| G7 | No reconnection time limit | Any reconnect resets score (B3); no grace window |
| G8 | Word pool is only 10 animals hard-coded | Very limited, easy to memorise |

### Assumptions (Unconfirmed)

| # | Assumption | Basis |
|---|---|---|
| A1 | `stroke_point` message includes `strokeId` | Required by sync logic in `handleStrokes` (`player.lastStrokeId = message.strokeId`) |
| A2 | `strokeId` is a monotonically-increasing integer assigned by the drawer | Implied by `stroke.strokeId > player.lastStrokeId` filter in `syncStrokes` |
| A3 | The frontend is responsible for generating `strokeId` values | Backend never assigns or validates them |
| A4 | CORS is not configured | No `cors` middleware found anywhere; WS + HTTP calls from a different origin **will fail** |
| A5 | No rate limiting or flood protection | No middleware found; rapid messages could cause issues |
| A6 | The `totalRounds: 5` value is not configurable at room creation | Hardcoded in `room.controllers.js:22` |

### Architecture Notes for Frontend

- **No global state snapshot exists.** The server never sends a full room state. The frontend must reconstruct state event-by-event from the moment of connection.
- **Message ordering** relies on TCP (WebSocket inherits this), so stroke messages should arrive in order within a single connection. However, if the drawer reconnects, `strokeId` ordering across reconnects is **Unknown**.
- **The WS server uses the raw `ws` library** — no Socket.IO namespaces, rooms, or acknowledgement API. The frontend must use a plain browser `WebSocket`, not a Socket.IO client.
- **CORS must be added** before the frontend can call the HTTP API from a browser on a different origin.
